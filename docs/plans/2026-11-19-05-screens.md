# Milestones 5 and 6: Browse and Details, design notes

**Goal:** the app's two real screens, on the data layer (milestone 3) and the design system (milestone 4). Browse lists the cached restaurants, searchable, with Open now, every state of spec §6.2 and pull-to-refresh. Details shows one restaurant, its hours and its menu (§6.3), and opens from `mrd://restaurant/{id}`. Both stay correct offline, and favourites agree between them.

**Spec:** §4.4, §4.5, §5.6, §5.7, §5.9, §6.2 to §6.6, §7.1 and §11 (AC-1 to AC-19 and AC-24). **Branch:** `feature/screens`, on `dev` plus milestone 3.

## Tasks, in order

1. **Design-system follow-ups from milestone 4's review:**
   - Material's remaining roles map to Mr D's tokens, and a test fails if any role keeps Material's baseline colour.
   - The details row never leaves a "·" at the start or end of a line.
   - `MrdRating` tells TalkBack "Rated 4.6".
   - The favourite toggle's callback passes the new value.
2. **M-5:** the paged list takes its minute ticks from the caller, so the ticks can stop with the screen.
3. **Images:** Coil 3.4.0's `ImageLoader`, from `:core:network`'s client, and `MrdApplication` as Coil's singleton factory.
4. **`:core:ui`:** the en-ZA formatters, `RestaurantImage` with the size resolver, and `RestaurantCard`.
5. **Browse:** `BrowseViewModel`, then the screen, replacing the placeholder.
6. **Details:** `DetailsViewModel`, then the screen, replacing the placeholder.
7. **The deep link:** the destination's `navDeepLink`, the intent filter, and the warm start.
8. **Release:** R8 keep rules if any are needed, proven on the release APK, then the gate, the emulator walk and the screenshots.

Each step lands with its tests, in its own commit.

## Decisions

- **State.** Each ViewModel exposes one `StateFlow` of an immutable state, shared `WhileSubscribed(5_000)` (§4.4).
  - **Browse:** `BrowseUiState`, holding the applied query, the toggle, the count, `SyncStatus`, connectivity and the current time. Which body to show (skeletons, error, results, no matches or empty area) and which banner are derived from it, in the ViewModel's module, and unit-tested. The paged list is a separate `Flow<PagingData>` with `cachedIn(viewModelScope)`, since `PagingData` can't live inside a `StateFlow`.
  - **Details:** `DetailsUiState`, holding the restaurant (loading, found, not found or unavailable), the `MenuState`, connectivity and the time. The menu is fetched straight away and never blocks the restaurant.
- **Saved state (AC-13).**
  - The search text is a `TextFieldState` held in the ViewModel, which Google's text-field guide encourages. It's created from `SavedStateHandle` and copied back on every change with `snapshotFlow`.
  - The toggle is `SavedStateHandle.getStateFlow`.
  - The query sent to the database is debounced by 250 ms. The first value, and an empty one, go straight through, so a restored query or Clear search doesn't wait.
  - The scroll position is `rememberLazyGridState()`. The grid isn't composed until the first page arrives, so a restored position isn't clamped to the top.
- **The ticker (M-5).** `cachedIn` keeps the paged flow collected for as long as the ViewModel lives, so the list can't stop a ticker of its own.
  - `RestaurantRepository.restaurants(query, openNow, ticks)` now reloads the list on the ticks it's given, and a tick in the minute the list was loaded for changes nothing.
  - Browse forwards the clock to it from inside its state's upstream, which runs only while the screen collects it. `collectAsStateWithLifecycle` collects only while the screen is at least STARTED, so the list stops reloading 5 seconds after the app goes to the background.
  - The same upstream runs `refreshIfStale()` when Browse becomes visible.
  - `count()` and `restaurant()` keep their own tickers, which their state flows already stop.
- **Banner.** Browse shows it whenever the device is offline or the last refresh failed. The wording is "You're offline", "Couldn't connect", or the device-storage message for `SyncError.Storage`.
- **Images.** `:core:network` provides Coil's `ImageLoader`. It uses the shared client's connections, but not its HTTP cache (`newBuilder().cache(null)`): photos go to Coil's own disk cache, so they can't evict the restaurant list's ETag entry from OkHttp's 10 MB cache. The resolver asks for `/large` for cards, the full-size photo for the header and `/small` for menu thumbnails. (It first asked for `/medium` and `/large`, which looked soft on a phone-width card in the walk.) The cuisine placeholder draws under each photo, so it shows while the photo loads, if it fails, and when it isn't cached offline.
- **Deep link.**
  - `navDeepLink<RestaurantRoute>(basePath = "mrd://restaurant")` on the Details destination.
  - The intent filter is on `MainActivity`, which becomes `singleTop`.
  - **Cold start:** `NavHost` handles the launch intent, and Navigation builds Browse with Details on top.
  - **Warm start:** an `OnNewIntent` listener, registered where the `NavController` is created, calls `handleDeepLink`. For an intent with `FLAG_ACTIVITY_NEW_TASK`, Navigation 2.10 restarts the task and builds the same back stack (`NavController.android.kt`, lines 597 to 615).
- **Details' not-found state.** A missing restaurant is "not found" only once a snapshot exists. When the snapshot first lands, the restaurant's query can report it missing a moment before it reports it found, so Details asks once more before saying it isn't there.
