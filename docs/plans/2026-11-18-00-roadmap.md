# Restaurant Discovery: implementation roadmap

> **For agentic workers:** this roadmap splits the work into milestones. Each milestone has its own detailed plan in `docs/plans/`, written just before the milestone starts. Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to carry out a milestone plan task by task.

**Goal:** Deliver everything in the design spec (`docs/specs/2026-11-18-restaurant-discovery-design.md`) as seven milestones, plus milestone 2b for the menus I added on 2026-11-19. Each milestone is working, tested software that merges into `dev` through its own pull request.

**Why milestones rather than one plan:**
- The spec covers build infrastructure, data, a design system, two screens and a release process. One plan with complete code for all of it would be thousands of lines long and written before any of it had been compiled.
- Each milestone plan is written against versions and APIs that the previous milestones have already proven.

---

## Version policy

Stability beats novelty. Older versions are fine wherever they're more proven.

- **Toolchain:** the AGP, Kotlin, KSP and Hilt lines that Google's Now in Android builds with, at their latest patch.
- **Libraries:** stable releases that had been out for at least four weeks on 2026-11-18 and worked with compile SDK 36 and Kotlin 2.3. Each library is also checked against the Kotlin version it was built with. Dependabot's androidx updates of 2026-11-19 (Compose BOM, Core, androidx.hilt and Navigation) need compile SDK 37, so the app compiles against 37 and still targets 36.
- **Validation:** on 2026-11-18 a throwaway spike build (four modules and an R8 release) passed with no warnings and no missing keep rules. It proved the toolchain together with Compose, Hilt, Navigation, Room, kotlinx.serialization, Robolectric and Konsist. The other libraries in the table are checked the same way when their milestone's plan is written.
- **Updates:** Dependabot proposes updates weekly, but only once a release is 30 days old (its `cooldown` setting). Its first round, merged on 2026-11-19 after CI passed, moved the toolchain past Now in Android's lines: AGP 9.5.1, Kotlin 2.4.21, KSP 2.3.12, Hilt 2.60.1 and Gradle 9.8.2, with kotlinx.serialization 1.12.0, Spotless 8.10.4 and ktlint 1.8.0.

The table gives the versions in `gradle/libs.versions.toml` and the wrapper. Two libraries planned for milestone 5, kotlinx.collections.immutable 0.4.0 and androidx.test ext-junit 1.3.0, turned out not to be needed.

**Order:**
- Milestone 2 comes before 3, because the data layer needs the live JSON.
- Milestones 2b, 3 and 4 touch separate modules and files, so they can run in parallel. Milestone 3 tests menu parsing with fixtures, not with milestone 2b's files.
- Milestone 5 needs 3 and 4. Milestone 6 follows 5, because both touch the navigation graph, and its menu needs 2b's files on `dev`.

## Definition of done for every milestone

1. Its plan is committed in `docs/plans/` before the work starts.
2. New logic has tests, written first where the code allows it.
3. These pass locally and in CI: `spotlessCheck`, `:app:lintDebug`, `testDebugUnitTest` (every module, including the pure Kotlin ones) and `:app:assembleRelease`, with no missing R8 keep rules.
4. UI milestones are walked on the emulator (light and dark theme, 200% font, rotation, and at least one offline or error path), with screenshots in `docs/qa/`.
5. The verifier agent (`.claude/agents/verifier.md`) writes a PASS report to `docs/qa/`.
6. Small commits with `Verified:` lines. The pull request uses the template, including AI notes, and anything the AI got wrong goes into `docs/ai/corrections.md`.
7. Franco reviews and merges the pull request.
